# MyVerse V1.0 production asset licensing audit

**Audit date:** 2026-10-30
**Repository / revision:** `dhomhafiz/myverse` / `e44078fc5a5b89dcbf89af9333a77eed1f3976e6`
**Result:** **NOT CLEARED FOR PUBLIC DEPLOYMENT**

This is a repository evidence audit, not legal advice. It records source claims and license pages that were available on the audit date; it does not establish ownership where the source-to-file chain is missing.

## Scope and method

- Read production references in `app/`, `components/`, `lib/`, `next.config.ts`, and `package.json`; compared them with all production and source-only asset files.
- Inspected all 15 GLB JSON chunks for `asset.copyright`, `asset.extras`, and embedded images. Inspected selected PNG/WebP metadata fields (`Artist`, `Copyright`, `Source`, `License`, `Software`, `Prompt`, and similar provenance fields); none supplied useful attribution data.
- Compared project documentation and `/credits` data/rendering with source pages and license pages that could be reached on 2026-10-30.
- The project owner identified the original Sketchfab source for the supplied keyboard archive; the integration record traces the supplied FBX into the optimized GLB. The archive is not present for an independent mesh comparison.
- `next.config.ts` uses `output: 'export'`. Next.js copies files in `public/` into the static export. The 14 unused unverified files listed below have been moved to `assets/source-only/unused-unverified/`, outside `public/`, so builds retain them in the repository but do not publish them.
- The complete asset inventory remains 35 files: 15 GLBs and 20 raster images. It consists of 21 production-directory assets (11 GLBs and 10 raster images) plus the 14 source-only files. Ten GLBs and ten images are referenced by production code. The GLBs contain 42 embedded images in total (26 in referenced GLBs, 16 in unreferenced GLBs); embedded textures inherit their containing model's provenance and license status, with textures in unverified models remaining unresolved.
- Production-use tracing included component imports, project/configuration arrays, Open Graph metadata, `room-preparation.ts` preload paths, GLB loader paths, dynamic work-page data and galleries, responsive image sources, and CSS references. None of the 14 excluded filenames is referenced by runtime code or fallback paths. The verified CC0 `public/models/football-compact.glb` is deliberately retained despite being unreferenced.
- The owner confirms that the two displayed guitars, bar stool, track light, and gravel bike were AI-assisted from reference pictures, optimized to GLB, and use generic designs with branding/logos removed. This is owner-declared creation history, not independently verified provider licensing. The unused compact guitar GLB is counted as an unused D file; its file-specific connection to the two owner-confirmed guitar models is not established.
- For images, the project record identifies the selected-work concept image as owner-supplied AI-generated illustrative art; the owner describes it as owner-directed AI generation. The unused PNG source is retained under `assets/source-only/unused-unverified/` and the used WebP derivative remains in `public/`. Provider/model, prompt/reference inputs, and terms are not recorded. The owner also identifies AI-assisted concept artwork on the Beyond the Code page, but the inspected generation notes do not map that page-level disclosure to an individual image file. The four displayed Beyond images therefore remain individually unverified; no usable generation history, source URL, or reference-image record establishes their file-specific origins. Their visual appearance alone does not establish whether any other image is original, AI-generated, licensed, or a third-party photograph.
- No standalone texture or environment-map files, HDR/EXR maps, local audio/video assets, or app-owned font files were found. There are no external image URLs or external `<script src>` references in production code. The only script in the root layout is inline Schema.org JSON-LD. External social/contact and news URLs are links, not embedded media.

## Status definitions

- **A — Verified for public use:** available evidence supports the file's source, license, and required attribution.
- **B — Self-created / original:** project records support original creation; separately identified reference-source questions are assessed on their own evidence and priority.
- **C — Attribution required:** the license permits the use, but required credit is missing or needs correction.
- **D — Unverified:** source, rights, or the source-to-file relationship is incomplete. Commercial use, redistribution, modification, and attribution requirements cannot be assumed.
- **E — Restricted:** available evidence says the intended use is not permitted.
