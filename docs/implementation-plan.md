## Phase 3 persistent room — architecture proposal

**Proposal recorded before implementation.** The current root page owns `RoomPreview`, so App Router replaces it when navigating to `/work`; the room image and camera pose are only temporary visual/camera handoffs, and chair/football simulation state is not persisted. The gallery owns a separate, demand-driven WebGL renderer. This proposal keeps canonical route URLs and the existing gallery while moving room ownership into the shared root layout.

- A root-level client experience shell will own one stable `RoomPreview` sibling beside the current route content. It mounts immediately on `/`, remains the same React component and Canvas when `/work` or `/work/[slug]` becomes active, and is not mounted on an initial direct work URL.
- The work route content remains the foreground fullscreen layer. During foreground navigation the room stays mounted, receives an inactive mode that disables pointer interactions and simulation updates, and uses the existing demand-driven R3F loop rather than rendering continuously.
- Direct work entry prioritizes the server-rendered work page. Shared preparation state will start with actual asset loading data where available; Canvas mounting is deferred until an explicit Return action so idle GPU work cannot compete with the gallery. The same readiness signal gates both the compact control and conditional return loader.
- A reusable destination configuration and one return-control contract will represent Projects now and permit later hotspot routes without implementing them. Room-origin return uses the live room and existing GSAP camera owner; direct-entry return mounts at the deterministic monitor-focus pose and remains covered until `SceneReadiness` reports a rendered frame.
- The room remains the source of truth for camera and interactive-object state. Route changes must not serialize visual snapshots for the normal room-origin journey. Snapshot exclusion remains for any fallback that still needs image capture.
- `SceneReadiness` remains the only source of render-ready state. Loading percentages are shown only from completed/total asset events; after assets settle, the UI reports finalization until the room's own stable-frame callback fires.

## Phase 2 coordinated entrance

One GSAP timeline in `useEntranceTimeline` owns boot exit, numeric camera/light channels, CSS room treatment, name/caption presentation, name collapse and final exploration readiness. `CameraRig` remains the only writer of Three.js camera transforms. Input stays disabled throughout `entering`, including the hero and collapse stages.

1. Fade the existing boot UI over an already compiled/rendered room. The lamp starts off and the room fill is dimmed; no blank frame is exposed.
2. Start at configurable workstation close-up poses in `lib/entrance.ts`. Desktop and portrait framing both show the monitors, with a clear path left of the chair.
3. Reveal monitor emissive glow, PC emissive rings, warm lamp and existing room fill in sequence. Reuse current materials and lights.
4. Pull back with smooth easing to the exact approved Home position, direction and lens. Hold Home while introducing the brand.
5. Temporarily apply subtle CSS blur/dimming and scanlines. Reveal large off-white **MOHD HAFIZ**, then **Hello, World!**. System Impact/Haettenschweiler typography supplies the condensed treatment without downloading a font. A short duplicate visual smear is aria-hidden; the actual name remains readable HTML.
6. Compress and translate the same heading toward an invisible measured brand anchor using position and scale. Fade caption/scanlines and clear the room filter during travel. At settlement the same heading reads **Mohd Hafiz** in the smaller UI typography. Do not create a duplicate semantic heading.
7. Final brand position: desktop left 32 px/bottom 28 px, 24 px type; mobile left 20 px/bottom 24 px, 20 px type. It stays separate from future navigation/hotspot labels.
8. Only after settlement enable Free Look and show **Drag to explore**. Final lights match the original scene intensities and the default camera exactly matches Home.

The normal sequence is approximately four seconds. Skip intro and Escape complete it safely. Reduced motion uses a brief simplified reveal at Home with no camera travel, blur, scanline or smear animation. Resize finishes safely at the responsive brand anchor.
